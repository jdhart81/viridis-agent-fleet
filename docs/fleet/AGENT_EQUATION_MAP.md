# Viridis Agent Fleet — Intelligence Bound Equation Map

*Every agent in the stable exists to move a variable in the equation. If it doesn't, it doesn't belong.*

## Fleet Architecture Principle: Software-Agnostic Intelligence

**Agents are pure intelligence services. Software is an interchangeable surface.**

Every Viridis agent is defined by its domain expertise and core functions — NOT by the software it connects to. Agents communicate via MCP (Model Context Protocol) or standardized APIs. They connect to any client, any platform, any rendering surface.

```
Agent = Domain Expertise + Core Functions + MCP Interface
Software = Interchangeable Surface (connected, not embedded)
```

**Three Horizons:**
1. **Now:** Agents connect to specific SaaS apps via API/MCP (Arboris GIS, Energy AI Worker, etc.)
2. **Near:** Agents packaged as MCP servers, connectable to ANY client (Claude, GPT, LangChain, custom apps)
3. **Future:** Agents render their own adaptive interfaces dynamically — the distinction between "agent" and "app" dissolves

**Invariant:** No agent MISSION.md may define the agent as dependent on a specific software platform. The agent's functions must be expressible as platform-independent MCP tools with typed schemas.

## The Equation

```
dI/dt ≤ P · D / (k_B · T · ln 2)
```

| Symbol | Meaning | Lever |
|--------|---------|-------|
| **dI/dt** | Rate of intelligence creation | The output — what we're maximizing |
| **P** | Power available to the system | Increase through distributed energy capture |
| **D** | Data richness (biodiversity, information diversity) | Preserve through conservation; measure to prove it |
| **T** | Thermodynamic cost / friction / noise | Reduce through efficiency, automation, friction removal |
| **k_B · ln 2** | Landauer limit — fundamental cost of a bit flip | Fixed by physics — our constraint, not our lever |

**The thesis:** Biodiversity loss (D↓) irreversibly reduces the ceiling on intelligence. Fossil energy dependence caps P. Institutional friction inflates T. The Viridis fleet attacks all three levers simultaneously.

**The business:** Agents that move P, D, or T generate revenue by delivering measurable value to stakeholders who benefit from that movement. Revenue flows back into the ecosystem to fund more lever-pulling. The flywheel compounds.

## The MISSION.md Protocol

Every agent gets a MISSION.md before release. The structure:

1. **Thesis Connection** — which variable(s) does this agent operate on, and how?
2. **Mission** — one sentence, grounded in the equation
3. **Value Proposition** — who pays, who benefits, what changes in the equation?
4. **Workflow Stages** — numbered, with entry/exit conditions
5. **Invariants** — testable conditions at each stage (binary pass/fail)
6. **Pre-Release Checklist** — the gate before deployment
7. **Known Gaps** — honest assessment of what's not ready
8. **Success Metrics** — how we know it's working

**The invariant principle:** If you can't test it, it's not an invariant — it's a wish. Every claim the agent makes about itself must be verifiable. The agent does not leave the stable until every invariant passes.
